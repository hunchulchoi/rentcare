# 개인정보·파일 보관과 삭제 (RENTCARE-16)

## 무엇을 모으나

| 항목 | 어디서 | 왜 |
|---|---|---|
| 대여 번호·차량 번호·차종·반납 장소·반납 시각 | 차량 앱 (대여 계약 입력) | 업체가 어떤 차의 접수인지 알기 위해 |
| 접수 유형·메모 원문·사용자 언어 | 차량 앱 | 상황 전달 |
| 차량 위치(좌표·주소)·연료/배터리 값·경고등 | 차량 (Pleos SDK) | 현장 파악 |
| 사진·영상 | 휴대폰 첨부 (`/m`) | 상황 증빙 |
| 업체 처리 기록(메모·조치·예상 시각) | 업체 화면 | 처리 이력 (업체 내부, 고객에게 상태만 표시) |

## 전송 전 고지

- 차량: 접수 화면에 받는 업체와 목적을 보여주고, "○○에 보내기에 동의"를 눌러야 전송된다.
  같은 화면에 "접수일로부터 90일 후 사진·영상과 함께 삭제" 고지.
- 휴대폰: 첨부 화면에 "이 접수 처리에만 쓰이며 90일 후 삭제" 고지.
- 업체: 상세 화면에 "삭제 예정" 날짜 표시.

## 보관기간과 삭제

- 접수일(`created_at`)로부터 **90일** (`RETENTION_DAYS`, 1–3650, 서버 설정). 차량·휴대폰 고지 문구의 90일과
  맞춰야 한다 — 값을 바꾸면 `car/app/src/main/res/values*/strings.xml`의 `retention_notice`와
  `web/src/lib/i18n.ts`의 `retention`도 같이 바꾼다.
- 서버(`web/src/lib/server/retention.ts`)가 시작할 때와 6시간마다 기간이 지난 접수를 지운다.
  1. 첨부 파일을 저장소(MinIO `attachments/…` 또는 `web/storage`)에서 삭제
  2. 모두 지워졌을 때만 접수 행을 삭제 — 첨부·첨부 코드·업체 처리 기록은 FK cascade로 함께 삭제
  3. 파일 삭제가 하나라도 실패하면 그 접수는 남기고 다음 실행에서 다시 시도 (기록 없는 파일이 남지 않게)
- 로그에는 건수만 남긴다(접수 번호·내용·위치 없음).
- Sablier로 컨테이너가 멈춰 있으면 다음 시작 때 실행된다.

## 차량 쪽

- 대여 종료("반납 완료") 시 차량에 저장된 대여 정보·접수 기록·첨부 코드를 모두 지운다 (RENTCARE-17, E2E S5).
- 차량 저장값은 Android Keystore AES-GCM으로 암호화.
